# 智能客服记忆管理方案（已收口）

本方案已并入正式状态契约，精确定义见 `customer_service_state_contract.md`。

## 当前规则

客服记忆分为两层：

1. 有界原始对话记忆：仅用于 Query 补全和语义理解，不是可信业务事实；按完整用户轮次
   裁剪，不允许以孤立的 assistant 消息开头，也不重复包含当前 `raw_query`。
2. 结构化业务状态：保存 Tool 已验证的商品、订单、焦点、售后草稿和待澄清动作；只有
   Tool 成功且 Result 契约通过后才能提交。

候选批次不使用固定三轮 TTL。只要没有新批次替代且候选回复仍在原始消息窗口中，候选
可以继续使用；候选回复一旦被裁剪，对应序数立即失效。结构化状态不得永久保留已经失去
可见依据的序数关系。

售后草稿被其他意图打断时保留，但恢复确认时必须重新经过显式确认和幂等门禁。
